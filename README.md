# 리앙에이지 CMS 화면설계서 — 배포 & 피드백 연결 가이드

퍼블(외주 퍼블리셔)에게 **링크 하나**를 공유하면, 서로 같은 화면에서 피드백을
주고받을 수 있게 만드는 방법입니다. 순서대로만 따라 하면 됩니다.

준비물: 구글 계정 하나, 깃허브(또는 Vercel) 계정 하나. 개발 지식 불필요.

---

## 전체 그림

```
   [화면설계서 HTML]  ──(링크 공유)──▶  퍼블 / 팀원
          │  화면(슬라이드)마다 피드백 등록·조회
          ▼
   [구글 Apps Script 웹앱]  ◀──▶  [내 구글 시트]
                                    ├─ 탭 "02 대시보드"   ← 그 화면 피드백만
                                    ├─ 탭 "07 문의 접수함"
                                    ├─ 탭 "09 채용 공고"
                                    └─ … 화면마다 개별 탭 자동 생성
```

- **★ 화면(슬라이드)마다 구글 시트의 개별 "탭"에 따로 쌓입니다.** 어떤 화면에 처음
  피드백이 달리면 그 화면 이름의 탭(예: `07 문의 접수함`)이 자동으로 만들어집니다.
- 퍼블은 **구글 시트를 직접 열 필요 없습니다.** 공유받은 웹페이지에서 각 화면을 보며
  코멘트를 쓰면 되고, 내가 남긴 코멘트도 같은 화면에서 바로 봅니다.
- Apps Script가 "내 계정 권한"으로 실행되므로 시트를 남에게 공유하지 않아도 됩니다.

---

## STEP 1. 구글 시트 만들기 (2분)

1. https://sheets.google.com → **빈 스프레드시트** 생성
2. 이름은 자유 (예: `리앙에이지 CMS 피드백`)
3. 시트 탭/컬럼은 손대지 않아도 됩니다. (코드가 자동 생성)

## STEP 2. Apps Script 붙여넣기 (3분)

1. 시트 상단 메뉴 **확장 프로그램 → Apps Script**
2. 기본 `Code.gs` 내용을 모두 지우고,
   **`리앙에이지_CMS_피드백_AppsScript.gs`** 파일 내용을 통째로 붙여넣기
3. 💾 저장 (Ctrl+S)

## STEP 3. 웹앱으로 배포 (3분)

1. 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴(유형 선택) → **웹 앱**
3. 설정:
   - **설명**: 아무거나 (예: v1)
   - **실행 계정(다음 사용자로 실행)**: **나**
   - **액세스 권한(액세스 권한이 있는 사용자)**: **모든 사용자**
4. **배포** → 처음이면 권한 승인 창이 뜹니다
   → 내 계정 선택 → "고급" → "(안전하지 않음)... 이동" → 허용
   (내가 만든 스크립트라 정상입니다)
5. 완료되면 나오는 **웹 앱 URL**을 복사
   → 형식: `https://script.google.com/macros/s/AKfy............/exec`

> ⚠️ 코드를 나중에 수정하면 **배포 → 배포 관리 → 편집(연필) → 버전 "새 버전" → 배포**
> 로 다시 배포해야 반영됩니다. (URL은 그대로 유지됩니다)

## STEP 4. HTML에 URL 연결 (1분)

`리앙에이지_CMS_화면설계서.html` 을 편집기로 열고, 위쪽 `<script>` 안의 이 줄을 찾습니다:

```js
const SHEET_ENDPOINT = "";
```

따옴표 안에 STEP 3에서 복사한 URL을 붙여넣습니다:

```js
const SHEET_ENDPOINT = "https://script.google.com/macros/s/AKfy............/exec";
```

저장하면 끝. 이제 피드백 패널 상단 배지가 **🟢 구글 시트 실시간 연결됨** 으로 바뀝니다.
(URL을 비워두면 🟠 오프라인 = 이 브라우저에만 저장 모드로 동작합니다.)

## STEP 5. 무료 서버에 올려 링크 공유하기

둘 중 **하나**만 하면 됩니다.

### 방법 A. GitHub Pages (추천 · 완전 무료)

1. https://github.com → 로그인 → **New repository**
   - 이름: 예 `rianag-cms` / **Public** / Create
2. **uploading an existing file** 링크 클릭 →
   `리앙에이지_CMS_화면설계서.html` 파일을 드래그해 업로드 → **Commit**
   - 팁: 파일명을 `index.html` 로 바꿔 올리면 주소가 깔끔해집니다.
3. 저장소 **Settings → Pages**
   - Source: **Deploy from a branch** / Branch: **main** / **/ (root)** → Save
4. 1~2분 뒤 상단에 나오는 주소가 공유 링크입니다:
   - `https://<아이디>.github.io/rianag-cms/`  (index.html인 경우)
   - 또는 `https://<아이디>.github.io/rianag-cms/리앙에이지_CMS_화면설계서.html`
5. 이 링크를 퍼블에게 전달 → 서로 피드백이 실시간 공유됩니다.

### 방법 B. Vercel (드래그로 더 간단)

1. https://vercel.com → GitHub 계정으로 로그인
2. **Add New → Project → (또는)** HTML 파일이 든 폴더를 드래그 업로드
3. 자동 배포된 `https://xxxx.vercel.app` 링크를 공유

> 수정할 때: 파일을 고쳐 같은 저장소에 다시 업로드(커밋)하면 링크는 그대로,
> 내용만 갱신됩니다.

## STEP 6. 나중에 카페24로 이관할 때

- 화면설계서는 "설계 문서"이고, 실제 CMS는 별도 구축입니다.
- 퍼블에게 넘길 것: 이 HTML(설계 기준) + 실측 규격(파일 내 표에 명시됨).
- 카페24는 PHP+MySQL을 지원하므로, 문서의 화면 흐름 그대로
  관리자 페이지(PHP)로 구현 가능합니다. (별도 진행)

## 자주 묻는 것

- **Q. 화면마다 시트가 따로 생기나요?**
  네. 각 화면(슬라이드)의 피드백은 **그 화면 이름의 개별 탭**에 쌓입니다
  (예: `03 프로젝트 목록`, `07 문의 접수함`). 해당 화면에 첫 피드백이 달리는 순간
  탭이 자동 생성되므로, 미리 탭을 만들 필요는 없습니다. 화면별로 의견을 분리해
  모아보기 좋습니다.

- **Q. 퍼블이 내 구글 시트를 보나요?**
  아니요. 퍼블은 웹페이지(화면설계서)만 봅니다. 데이터는 내 시트에 쌓이고,
  Apps Script가 내 권한으로 중계하므로 시트 공유가 필요 없습니다.

- **Q. 로그인/비밀번호가 필요한가요?**
  이 설계 문서 단계에서는 불필요합니다. 링크를 아는 사람만 접근합니다.
  (실서비스 CMS는 관리자 로그인 1개를 두는 것을 권장 — CMS-01 화면 참고)

- **Q. 배지가 🔴 "연결 실패"로 뜹니다.**
  ① SHEET_ENDPOINT URL이 `/exec` 로 끝나는지 ② 배포 액세스 권한이
  "모든 사용자"인지 ③ 코드 수정 후 "새 버전"으로 재배포했는지 확인하세요.
  실패해도 입력한 피드백은 로컬에 임시 보관되며, [↻ 새로고침]으로 재시도됩니다.
